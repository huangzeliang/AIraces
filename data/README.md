# data 目录说明

运行期数据目录，应用所有读写都落在这里（JSON 文件 + 原子写入）。

| 文件 | 说明 |
| --- | --- |
| `plans.json` | 应用运行时主数据（计划 / 待办 / 任务 / 提醒 / 反馈 / 异常 / 日志），启动时若不存在会自动初始化；计划与任务带 `user_id` 归属到账号 |
| `sample_data.json` | 示例实例数据（只读样例），字段与 `plans.json` 完全同构，可直接替换用于演示 |
| `users.json` | 账号与角色（`id` / 姓名 / 邮箱 / 角色 / 状态 / `password_hash`）；角色仅两种：`管理员`、`普通用户` |
| `settings.json` | 系统设置（主题、巡检间隔、免打扰时段、通知渠道） |

## users.json 说明

- `id` 采用 `U001` 起的编号，并作为 `plans.json` 中 `plans[].user_id` / `tasks[].user_id` 的归属依据；普通用户只能看到自己名下的数据。
- 密码通过 `werkzeug.security`（pbkdf2:sha256）哈希存储，不保存明文；管理员在「用户管理」页可重置密码。
- 演示账号：管理员 `ruoxi.lin@example.com`（U001）、普通用户 `yuhang.chen@example.com`（U002）、`zimo.zhou@example.com`（U004），初始密码均为 `123456`；`sihan.wang@example.com`（U003）为「停用」状态示例。
- 启动时 `app.py` 会自动补齐旧数据：角色 `运营` / `编辑` 归一为 `普通用户`，缺少密码哈希的账号补默认密码，缺少 `user_id` 的任务按所属计划补齐。

## sample_data.json 说明

按软需说明书 1.3 数据字典构造的一组完整实例，覆盖 3 条主线：

- **3 个计划**（监管报送 / 支付系统投产 / 知识库建设），8 条待办，18 个任务
- **6 条提醒**：覆盖 4 种渠道（页面弹窗 / 桌面通知 / 企业微信 / 钉钉）与 3 种状态（未读 / 已读 / 已忽略）
- **5 条反馈**：完成 / 延期 / 取消各类型齐全
- **2 条导入异常**：优先级非法、耗时非法（原因文案与导入校验一致）

内置演示点：`T007` 高优先级任务已延期且超期（触发改期建议）、`T015/T018` 父子任务、`T013` 已取消、`T006/T012/T017` 待安排（未排期）。

### 数据约定

- ID 规则：计划 `P+日期+序号`、待办 `D001`、任务 `T001`、提醒 `R001`、反馈 `F001`、异常 `E001`
- 时间均为 ISO8601（秒级），排期落在工作日 09:00–18:00 且互不重叠
- `depends_on` 前置依赖均已满足（依赖任务完成时间早于本任务开始时间）
- `is_demo` 固定为 `false`：仅进阶 / 演示专用数据才置 `true`

### 使用方式

应用实际读取的是 `plans.json`，`sample_data.json` 不会被自动加载。用它做演示时：

```bash
cp data/plans.json data/plans.json.bak      # 先备份运行数据
cp data/sample_data.json data/plans.json    # 换上示例数据
```

刷新浏览器即可看到示例内容；恢复时把 `.bak` 拷回即可。
