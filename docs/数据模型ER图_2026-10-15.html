①关系总览

核心链路：用户 → 计划 → 待办 → 任务；任务表是执行层枢纽，向上双归属（计划 / 待办），向下承载提醒、反馈、日志与改期忽略记录，并含两组自关联。

#关系基数连接字段说明
01users → plans1:Nuser_id计划归属用户；应用当前固定 U001，为软关联
02plans → todos1:Nplan_id计划拆解出的待办
03plans → tasks1:Nplan_id任务所属计划（保留冗余归属，便于按计划统计）
04todos → tasks1:Ntodo_id任务所属待办
05tasks → tasks1:Nparent_task_id父子任务自关联（空为顶级任务）
06tasks ↔ tasksM:Ndepends_on[]前置依赖自关联，数组存储多对多
07tasks → reminders1:Ntask_id提醒挂载任务（巡检生成 / 临期 / 超期）
08tasks → feedbacks1:Ntask_id反馈挂载任务，附 prev_state 变更前快照
09tasks → logs1:Ntask_id操作日志挂载任务
10tasks → ignored_suggestions1:Ntask_id|时间弱实体：改期建议忽略记录，无独立主键
11exceptions → tasks软关联处置补录导入异常修正 / 补录校验通过后新建任务
12CSV 导入 → tasks / exceptions数据流—合法行入库为任务，非法行记入异常表
单例实体（settings / scan_state）与主数据（users.json）不参与上述外键关系，详见第④节。

④存储与约定

data/ 为运行期数据目录，应用所有读写都以 JSON 文件 + 原子写入落在这里。

文件内容说明
data/plans.jsonplans · todos · tasks · reminders · feedbacks · exceptions · ignored_suggestions · logs · scan_state应用运行时主数据（8 个集合 + 1 个状态对象），JSON + 原子写入，启动时若不存在自动初始化
data/users.jsonusers用户与角色（登录 / 视图角色）
data/settings.jsonsettings（单例）主题、巡检间隔、免打扰时段、通知渠道
data/sample_data.json与 plans.json 同构的示例数据只读样例，不自动加载；演示时手工替换 plans.json
关联完整性校验（2026-10-15 全量通过）：tasks 的 plan_id / todo_id、reminders / feedbacks / logs 的 task_id、tasks.depends_on 引用、ignored_suggestions 的 task_id 均指向有效记录，悬挂引用 0 条；plans.user_id 为软关联（当前固定 U001，不参与强校验）。

ID 规则与时间约定

  • 计划：P + 日期 + 序号，如 P20260921001
  • 待办 / 任务 / 提醒 / 反馈 / 异常 / 日志：各自独立序号 D001 · T001 · R001 · F001 · E001 · L001
  • 用户：demo-001 …（应用当前以固定 U001 引用）
  • 改期忽略：复合键「task_id|忽略时间」，如 T009|2026-10-14T09:15:00
  • 时间：ISO8601 秒级；排期落在工作日 09:00–18:00 且互不重叠（示例数据约定）
