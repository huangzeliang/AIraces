# Northstar UI 主题开发规范

本文档根据 `PC_Web_UI_4_Demos` 中的第 2 套 **深海极光（Midnight Pulse）**、第 4 套 **活力拼图（Pop Bento）** 及其设计规范整理，用于指导后续 AI 与开发者实现一致的页面 UI。

本文档是所有新增、修改页面的必读开发约束。手机端、平板端和 PC 端适配属于页面功能的默认交付范围，无需用户再次提出“适配移动端”。“必须 / 禁止”为验收要求，“建议”为可按页面内容调整的方案。本文档规定目标行为，不代表现有页面已全部达标；开发时必须检查实际代码并完成本次涉及页面的适配。

## 1. 使用范围与主题切换

- 白天主题：第 4 套「活力拼图」，对应 `html[data-theme="day"]`。
- 夜晚主题：第 2 套「深海极光」，对应 `html[data-theme="night"]`。
- 所有页面必须通过语义化 CSS 变量取色，不能在页面专属 CSS 中散落硬编码的主题色。
- 主题选择通过 `localStorage` 保存为 `northstar-theme`；公共逻辑位于 `frontend/static/js/theme.js`。
- 新页面继承 `frontend/templates/layout.html`，公共 Token 位于 `frontend/static/css/tokens.css`。

## 2. 通用界面原则

| 项目 | 规范 |
| --- | --- |
| 布局 | 同一套页面支持手机、平板与 PC；PC 使用侧栏 + 顶栏 + 自适应内容区，内容最大宽度 1610px；手机端使用单栏和可访问的替代导航。 |
| 栅格与间距 | 使用 4px 增量；常用间距为 8 / 12 / 16 / 20 / 24 / 32px。 |
| 圆角 | 白天主题 14–21px；夜晚主题 11–18px。 |
| 字体 | `Inter / PingFang SC / Microsoft YaHei / sans-serif`；白天允许 Rounded 风格标题。 |
| 控件 | 标准高度 40–44px；键盘焦点须有 3px 可见描边。 |
| 动效 | 150–240ms，仅用于 hover、切换、反馈；必须尊重 `prefers-reduced-motion`。 |
| 响应式 | 必须遵守第 8 节：≤980px 收窄侧栏；≤700px 使用移动导航及单栏；仅表格、时间轴等指定区域允许局部横向滚动。 |
| 可访问性 | 不只靠颜色表达状态；状态必须包含文字、图标或圆点；按钮与输入框应有可访问名称。 |

## 3. 白天主题：活力拼图（Pop Bento）

### 3.1 气质与适用场景

明快、年轻、易记。以大胆蓝、日光黄、柔和粉构建 Bento 信息卡，适合工作概览、创意平台、团队协作与引导性页面。

### 3.2 设计 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#F6F7FF` | 页面背景 |
| `--surface` | `#FFFFFF` | 面板、卡片、弹窗 |
| `--text` | `#171A3B` | 主文字 |
| `--muted` | `#626D88` | 次级文字 |
| `--subtle` | `#748099` | 辅助标签、表头 |
| `--border` | `#DCE0EF` | 控件和面板边界 |
| `--accent` | `#3D55ED` | 主操作、选中态、链接 |
| `--accent-soft` | `#EDF0FF` | 主色弱强调背景 |
| `--green` | `#188A70` | 成功、启用 |
| `--purple` | `#9D62EF` | 管理、辅助强调 |
| `--orange` | `#D16B47` | 警告、停用、危险操作 |
| Hero 背景 | `#F9E47E` | 首页或页面主视觉 |
| Hero 浮层 | `#FF91A0` | 少量趣味提示 |
| 阴影 | `3px 3px 0 #E3E6F4` | 卡片的偏移实色阴影 |

### 3.3 视觉规则

- 卡片使用白色底、18px 左右圆角、偏移实色阴影；hover 时可把偏移阴影加强到 5px。
- 主按钮为蓝底白字；只保留一个页面主操作，例如“新增用户”。
- Hero 可使用黄色大色块，并辅以粉色小标签；饱和色块应控制在页面面积的三分之一以内。
- 选中导航使用纯蓝底、白色文字和偏移阴影；弱化导航仅使用浅蓝 hover。
- 图标放在浅色圆角方块中；同一页面不要同时出现超过 3 种强强调色。

## 4. 夜晚主题：深海极光（Midnight Pulse）

### 4.1 气质与适用场景

沉浸、理性、偏技术感。以深海底色、青绿色焦点、半透明层级与克制发光来突出数据与实时信号，适合数据报表、监控、AI 工具与分析页面。

### 4.2 设计 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#080D1A` | 页面背景 |
| `--surface` | `#111C2E` | 面板、卡片、弹窗 |
| `--side` | `#0B1322` | 侧栏 |
| `--top` | `#0B1526E6` | 半透明顶栏 |
| `--text` | `#F1F6FF` | 主文字 |
| `--muted` | `#A1B0C6` | 次级文字 |
| `--subtle` | `#8798B1` | 辅助文字 |
| `--border` | `#24344B` | 面板边界、网格线 |
| `--accent` | `#4CE1CF` | 核心信号、主操作、焦点 |
| `--accent-soft` | `#103D43` | 青绿色弱强调背景 |
| `--green` | `#57DEAA` | 成功、启用 |
| `--purple` | `#B39BFF` | 次级数据强调 |
| `--orange` | `#FFA96F` | 警告、停用 |
| Hero 背景 | `#112B3B → #101B36` | 可叠加低透明蓝绿径向渐变 |
| 阴影 | `0 8px 24px rgba(0,0,0,.12)` | 低对比层次阴影 |

### 4.3 视觉规则

- 面板采用深蓝灰背景和低对比边框；不要用纯黑大面积替代层级。
- 核心操作、选中导航、数据曲线统一使用极光青；荧光仅用于重点，不可大面积铺满。
- Hero 可使用青蓝渐变和细圆环，数据卡片可采用半透明玻璃质感，但文字对比度必须足够。
- 选中导航使用深青渐变、青色文字，并可用 3px 左侧内嵌高光表示当前页。
- 数据图表网格线使用 `#25354C`，主曲线使用 `#4EE5D4`，辅助数据可使用蓝灰或紫色。

## 5. 组件规范

### 导航与顶栏

- 所有页面共享侧栏和顶栏，包括工作概览、用户管理、数据报表、系统设置及后续业务页面。
- 当前页面必须同时在侧栏高亮，并在顶栏面包屑显示页面名称。
- 主题按钮始终位于顶栏右侧，使用太阳/月亮图标及“白天/夜晚”文本；不能只使用图标。

### 卡片与统计

- 统计卡片包含：指标名称、图标、主数值、简短说明或状态。
- 白天态重点使用 Bento 色块和偏移阴影；夜晚态改为深色分层和克制光晕。
- 数值字号建议 29–32px，使用等宽数字特性时应保持对齐。

### 表格、筛选与状态

- 表头使用弱化文字，行 hover 使用弱强调背景。
- 搜索框与筛选控件高度统一为 40px。
- 状态标签需要背景色、前置状态圆点和文字：启用使用绿色，停用使用橙色。
- 删除为危险操作，必须保留二次确认。

### 弹窗与反馈

- 弹窗采用当前主题的 `--surface`，圆角约 20px，遮罩带轻度模糊。
- 表单字段必须带清晰 label；必填项以文字或星号标注。
- 成功和错误反馈使用短提示条，不能只通过页面颜色变化表达结果。

## 6. 新页面开发清单

1. 在 `frontend/templates/pages/` 新建页面模板，并继承 `layout.html`。
2. 在 `frontend/static/css/pages/` 添加同名页面专属样式；只使用公共 Token。
3. 在 `frontend/static/js/pages/` 添加同名页面专属脚本；不要复制主题切换代码。
4. 为页面添加后端 GET 路由，并传入 `active_page`、`page_name` 等布局所需变量。
5. 在白天和夜晚主题下检查：文字对比度、按钮状态、表格可读性、窄屏布局和键盘焦点。
6. 按第 8 节实现各端布局及交互，按第 9 节逐项验收；不能仅添加媒体查询后就视为适配完成。

## 7. AI 开发约束

- 优先复用 `layout.html`、`components/` 和语义 Token，禁止重新实现一套侧栏或主题切换。
- 页面专属调整放在对应 `pages/<name>.html`、`css/pages/<name>.css`、`js/pages/<name>.js`；当适配需要修复公共导航、顶栏、弹窗等共享能力时，允许修改公共文件并说明影响范围，同时回归所有使用该组件的页面。禁止在页面样式中重复覆盖整套公共框架。
- 不引入外部 UI 框架、在线字体或图片依赖；当前项目应保持 Flask + 原生 HTML/CSS/JS。
- 新增颜色先判断是否能映射到现有 Token；确有必要时，在 `tokens.css` 中同时定义白天和夜晚的语义值。
- 保持白天主题的活力与夜晚主题的克制：不要把白天的高饱和拼图色直接搬到夜间态，也不要把夜晚的大面积发光直接搬到白天态。
- 必须按第 10 节执行“读取规范 → 明确各端行为 → 实现 → 验收 → 报告”的开发流程；未执行的验证必须如实标注。

## 8. 手机、平板与 PC 多端适配要求

### 8.1 视口与统一断点

所有宽度均指 CSS 像素，以视口可用宽度判断布局，不按设备型号、User-Agent 或触摸能力推断屏幕大小。支持 320px 起的视口；大屏内容居中，不随宽度无限拉伸。

| 视口宽度 | 导航与内容布局 | 内容左右内边距 |
| --- | --- | --- |
| ≤700px（手机及窄窗口） | 隐藏常驻侧栏，同时提供菜单按钮与移动导航；内容单栏，标题和操作区可换行 | 16px；≤360px 可收紧为 12px |
| >700px 且 ≤980px（平板及紧凑窗口） | 74px 图标侧栏；卡片建议 1–2 列，复杂主次区域上下排列 | 24–25px |
| >980px（PC） | 完整侧栏、顶栏；按内容使用多列栅格，内容最大宽度 1610px | 32–42px |

- 700px 和 980px 必须分别落入手机、紧凑布局；媒体查询按明确顺序覆盖，不能在边界同时出现两套导航或导航缺失。
- 允许因组件内容在 1080px、1180px 等宽度提前换行或降列，但不得改变公共导航的统一断点，也不得通过大量设备专属断点逐一补丁。
- 保留 `layout.html` 中的 `width=device-width, initial-scale=1`；禁止设置 `user-scalable=no` 或限制用户缩放。
- 统一使用弹性布局、Grid、百分比和 `max-width`；禁止用整页缩放、固定 PC 画布或 `transform: scale()` 实现移动适配。
- Grid 可收缩列使用 `minmax(0, 1fr)`，Flex/Grid 内容项按需设置 `min-width: 0`；图片、SVG、Canvas 必须适应容器宽度。固定宽度只用于图标等受控元素或明确的局部滚动内容。
- 长标题、中文连续文本、长 URL 和无空格标识不得撑破容器；按语义换行（如 `overflow-wrap: anywhere`）或截断，并提供可点击/聚焦查看全文的入口，不能仅依赖 hover 或 `title`。

### 8.2 导航与顶栏

- 手机端隐藏侧栏时，必须同时提供始终可达的菜单入口，支持访问与 PC 相同的全部业务页面，并显示当前页面。禁止仅隐藏 `.sidebar` 导致页面入口消失。
- 移动导航优先复用公共导航条目与路由；如采用抽屉，菜单按钮必须提供可访问名称、`aria-expanded` 和 `aria-controls`。
- 抽屉支持打开、关闭按钮、遮罩点击和 Escape 关闭；打开时焦点进入抽屉并限制在其中、背景不可交互且锁定背景滚动，关闭后恢复背景状态和触发按钮焦点。
- 从手机切回宽屏时，必须清理已失效的遮罩、滚动锁和焦点限制；当前页与主题状态不得丢失。
- 紧凑侧栏的图标链接保留可访问名称，并为鼠标悬停或键盘聚焦提供文字提示。
- 顶栏空间不足时优先收起次要面包屑，保留当前页名称、导航入口、主题切换和业务必需操作。主题切换仍保留可见的“白天/夜晚”文本，禁止在手机端仅隐藏 `.theme-label`。

### 8.3 卡片、筛选、表单与操作

- 手机端统计卡片和主次内容区改为单栏，按 DOM 中的业务优先级排列；不通过 CSS 重排造成视觉顺序与键盘顺序不一致。PC 在空间允许时恢复多列。
- 标题、筛选项、标签页、批量操作和分页必须换行或采用明确的局部滚动交互；手机搜索框优先占满一行，按钮不能被挤出屏幕。
- 手机端表单采用单栏，输入框和选择器不超出容器，label、校验错误及帮助文字完整可见；可输入的表单控件字号至少 16px，避免手机输入时意外放大。
- 手机端按钮、图标按钮、关闭按钮等触摸目标至少为 44×44px（含可点击内边距），相邻目标建议间隔至少 8px；PC 控件维持 40–44px 的基础高度。
- 不得依赖 hover 才显示编辑、删除、提示或详情入口；触摸和键盘必须可完成同样的业务操作。危险操作继续保留二次确认。
- 手机端允许将低频操作放入有明确名称的“更多”菜单，但不能删除功能；隐藏装饰图形时保留业务数据、状态及操作入口。

### 8.4 表格、图表、时间轴及复杂内容

- 表格可采用移动卡片或独立 `overflow-x: auto` 容器。采用卡片时保留字段名称、关键数据、选择能力及行操作；采用滚动表格时保留表头语义、显示滑动提示，并确保最右侧操作可滚动到达。
- 图表、时间轴、树图等应优先自适应；确需最小宽度时，只允许其外层指定容器横向滚动，提供区域名称、键盘聚焦与滚动能力。不能让内部最小宽度撑宽页面。
- 图表缩放后标签不得重叠或被裁切；悬停提示必须有点击/聚焦或文字数据等替代方式。
- 页面根节点不得出现横向滚动。禁止用 `body { overflow-x: hidden; }` 掩盖溢出、裁掉按钮或数据；允许的横向滚动区域必须在交付说明中列出。

### 8.5 弹窗、固定区域与手机系统界面

- 弹窗宽度不超过视口扣除两侧至少 12px 留白，内容过高时内部可滚动；关闭、取消、提交及错误提示必须可达，不得固定高度裁掉表单。
- 弹窗和抽屉使用动态视口高度约束（`dvh`，并提供 `vh` 回退），处理横屏、短视口、浏览器地址栏及软键盘弹出后的可用空间；禁止对整个页面强制固定高度。
- 吸底操作条、浮动按钮及通知须考虑 `env(safe-area-inset-bottom, 0px)` 等安全区，并给正文预留占位空间；刘海屏、底部手势条不能遮挡关键操作。
- 键盘聚焦输入框后，字段、错误信息与提交入口可以通过滚动到达；关闭弹窗后恢复页面原有滚动及焦点。
- 旋转屏幕、调整窗口及跨断点切换不得清空已输入表单、筛选条件、已选记录或重复提交请求。避免维护两套独立的手机/PC 业务逻辑与状态。

## 9. 多端验收标准

适配完成必须同时满足视觉和功能要求。以下检查适用于所有本次新增或修改页面；涉及公共布局、导航或组件时，必须覆盖所有受影响页面。

| 检查维度 | 必须执行的验收 |
| --- | --- |
| 代表视口 | 320×568、375×812、390×844、768×1024、1024×768、1440×900、1920×1080；另检查手机横屏 844×390 |
| 断点边界 | 分别检查 699 / 700 / 701px、979 / 980 / 981px 宽度，以及本次新增的组件断点两侧 |
| 双主题 | 上述视口与边界均检查白天、夜晚；主题切换后仍可操作，刷新后主题保留 |
| 溢出 | 根节点 `document.documentElement.scrollWidth <= document.documentElement.clientWidth + 1`；另外人工确认无裁切及遮挡，局部滚动区的数据和操作全部可达 |
| 业务流程 | 在手机和 PC 各完成一次本次涉及的主要流程，如导航、搜索筛选、分页、新增、编辑、删除确认及取消；验证其实际结果 |
| 状态与内容 | 检查加载、空数据、成功、错误，以及长标题、长 URL、多条记录和表单校验错误；不能只检查默认示例数据 |
| 输入与无障碍 | 检查触摸操作、Tab 焦点顺序、可见焦点、Enter/Space 操作按钮及 Escape 关闭弹层；200% 缩放后主要内容和操作仍可用 |
| 切换与遮挡 | 打开导航/弹窗后跨断点切换和旋转视口，检查遮罩、滚动锁、表单状态；手机软键盘及安全区下关键操作仍可达 |

- 使用浏览器检查实际渲染和交互；已有自动化工具可补充视口切换、根节点溢出断言及业务流程验证。截图只能证明外观，不能代替交互验收。
- 软键盘、浏览器系统栏、安全区等需真机或具备相应能力的环境验证；桌面浏览器修改视口不能作为这些项目已通过的依据。
- 发现断点间的溢出或交互缺陷必须修复；验收宽度是采样点，布局必须在这些宽度之间连续可用。
- 无法运行浏览器、真机或部分流程时，交付时逐项标注“未验证”、原因及复验步骤，不得宣称多端验收全部通过。

## 10. AI 页面开发执行流程与交付要求

1. **先读取**：阅读本规范，并检查 `layout.html`、公共 CSS/JS、目标页面及其复用组件；不得因为页面已有媒体查询就判定适配完成。
2. **明确行为**：编码前列明手机、紧凑布局与 PC 下的导航、内容列数、筛选、表格/图表、弹窗及主要操作行为；业务页面不包含某组件时标注“不适用”。未指定细节时使用第 8 节默认方案继续实现。
3. **落实功能**：默认同步实现各端布局与交互，复用接口、数据和事件逻辑。若目标页面依赖的公共能力不达标，修复公共能力并回归，不能仅记录问题后把页面认定为完成。
4. **完成验证**：按第 9 节检查目标页面和受影响页面，修复发现的问题；新增交互需覆盖打开/关闭、确认/取消和错误路径等实际行为。
5. **如实交付**：说明改动文件、各端布局和交互变化、公共组件影响范围、允许局部滚动的区域、已验证的视口/主题/流程及结果；单独列出未验证项与复验步骤。

AI 自检清单（适配开发交付前逐项确认）：

- [ ] 手机、平板、PC 布局连续可用，页面无整体横向溢出或关键内容裁切。
- [ ] 手机导航可进入全部业务页面，主题切换及主要业务操作可达。
- [ ] 表格/图表局部滚动或卡片方案保留数据与操作，长内容不撑宽布局。
- [ ] 手机触摸目标、表单字号、键盘焦点、弹窗滚动及关闭行为符合要求。
- [ ] 白天/夜晚主题、断点边界及手机横屏已验证，跨断点不丢业务状态。
- [ ] 交付说明包含实际验证结果；未验证项目明确列出，没有用静态代码审查冒充运行验收。
